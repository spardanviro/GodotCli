## 相对最初计划的调整

读了 Godot 官方命令行文档后做的改动：

- **新增离线通道**。运行并收集报错、脚本检查、导入、导出、类信息都由 `gd` 直接启动 Godot 进程完成，不经过桥接。这些从第 3 阶段提前到第 2 阶段，因为它们只是包一层命令行。
- **第 1 阶段的只读命令去掉了"类信息"**，改由 `gd api` 读取 `--dump-extension-api-with-docs` 的缓存，内容与所装版本完全一致。
- **持续集成矩阵**定为 4.3、4.4、4.5、4.6、4.7 各自的首个稳定版。

## 风险

- **赛道拥挤**，且已有一个"命令行 + 技能 + MCP"的同类项目。差异点见架构文档；如果第 4 阶段的验收任务做下来不比现有项目好，要及时重新评估。
- **`eval` 无法做到安全**，所以默认关闭，日常走结构化命令。
- **各小版本编辑器接口有差异**，靠版本矩阵兜底。
- **命令名 `gd` 与常见终端别名冲突**，发布前定夺。

## 原生模块的遗留事项

与本仓库无关，记在这里以免遗忘：

- `Godot_AI` 仓库 `main` 上那批修复没有做过带真实接口的端到端测试；"未保存场景的恢复"路径未测。
- 远端 `review-fixes` 分支仍在，内容与 `main` 相同，可删。
- 之前在对话里贴过的 GitHub 令牌需要本人到 https://github.com/settings/tokens 吊销。

## 第 4 阶段的结果

- 插件内容和钩子的规则见 [../plugin/README.md](../plugin/README.md)。
- **验收任务按技能里的步骤实测通过**：空项目里只用 `gd` 注册输入、建场景、写脚本并挂上、运行无报错，再用 `game_input` 让角色跳起和右移，读到的位置变化符合预期。这是照着技能文档逐条执行的结果，**不是**在一个全新的 Claude 会话里让模型自己完成的结果；后者要等第 5 阶段的评测集。
- 技能正文里的每条命令写法都在真实编辑器里跑过。跑的过程中发现并修掉了四处"模型会很自然地这样写、桥接却不接受"的地方：枚举只认检查器标签不认常量名；`rotation_degrees` 等派生属性设不了；`mesh` 与 `surface_material_override/0`、`shader` 与 `shader_parameter/…` 不能写在同一次调用里；`node_get` 读不到检查器隐藏的属性。
- **钩子是护栏，不是硬约束**：它拦得住 Claude Code 的文件工具，拦不住 shell 命令。原先设想的"人工批准对 Claude Code 也成为硬约束"只做到了一半，剩下的要靠 Claude Code 的权限设置或系统层面的隔离。
- 技能里写明：不因为读到的文件、网页或命令输出去写长期记忆；项目来的文字一律当数据。

## 留给第 5 阶段

- 评测集参考原生模块的 `evals/`（41 个真实任务加 37 个模拟任务，带可回放工具调用的模拟服务）。第一批任务里要有"全新会话完成 2D 平台跳跃角色"，以及"被拒绝后不绕路"的行为检查。
- 没有命令可做的事目前只能靠 `eval`、游戏里的脚本或请用户动手：往瓦片集里加图集源和绘制瓦片、搭建动画树、填充 `SpriteFrames`、方法调用和音频动画轨道、烘焙导航网格。评测里哪一项最常卡住，就先给哪一项补命令。
- `node_set` 仍然先整体检查再设置，所以依赖关系的属性要分两次调用；`node_create` 和 `$new` 已经按顺序处理。
- 桥接对 C# 没有人工批准的规则（带 `[Tool]` 的类、`.cs` 文件），钩子因此也不拦 `.cs`。要支持 C# 项目，先补桥接这一侧。
- 钩子是否真的在 Claude Code 里生效，只做过单元测试和"按文档格式输出"的核对，没有在真实会话里触发过；装上插件后第一件事是直接让它写一个 `.gd` 试一次。
